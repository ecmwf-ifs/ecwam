ecWAM
-----

## Building

- Build ecwam using the bundle builds as described in `README.md`.
- "bundle" refers to ecbundle, a lightweight package manager configured via
  the bundle.yml config file in the ecland root-dir.
    - In a nutshell it packs all of the dependencies into a super cmake space
      and builds them as one large cmake project.
- All of ecWAM's dependencies, and their default build options are encoded in `package/bundle/bundle.yml`.
- Commonly used build options are exposed in the bundle via flags. Build types are specified via `--build-type=<btype>`.
- If on the ECMWF Atos hpc2020 system, use its default arch to build.
- Use the ninja build backend when possible, specified via an extra `--ninja` flag to the bundle build line.
- Add the `--with-fckit` flag to all bundle builds.

- The bundle create step is typically run only once for a fresh clone.
    - Once this is complete, there is an ecbundle checkout in the root dir, explore this
      if you need more insight into ecbundle.
    - If bundle.yml is updated, then we need to run create again, possibly with `--update` or even
      `--forced-update` if dependency versions were also updated.

- The dependencies will then be checked out as subdirs in source/.
- These are not git submodules, and each is a full git repo in its own right.

- The bundle create and build steps can be fragile, rerun them once if they fail.

## Testing

- Test by running `ctest` inside the `<build-dir>/ecwam` subdirectory.
- Also do static checks with the fortls language server if it's available.
- Before running the tests, you have to source the env.sh in the build dir.

## External API

- The external API comprises of:
  - YOWGRIBHD
  - YOWCOUP
  - YOWODB
  - YOWMPP
  - YOWMAP
  - YOWPCONS
  - YOWGRID
  - YOWTEST
  - YOWSPEC
  - YOWGRIB_HANDLES
  - WAVEMDL
  - WVALLOC
  - WVDEALLOC
  - WVWAMINIT1
  - WVWAMDECOMP

- Don't make non backwards compatible changes here without asking the user first.

## Interface generation

- C-style include with a name matching "*.intfb.h" are auto-generated by the build system.

## External dependencies

- The following is a non-exhaustive list of all modules and subroutines:
  - PARKIND1
  - YOMHOOK
  - GRIB_API
  - MPL
  - MPL_MPIF
  - OML
  - FIELD_*_MODULE
  - NEMOGCMCOUP_*

- For these externally imported modules, expect to see missing module lsp diagnostics warnings
